# DeepSeek 分支交叉检查（2026-10-18）

本轮以 `codex/area-reduction-20261018` 的 `41752dc` 为基线，交叉检查 `deepseek/area-reduction-20261018` 的 `0b544c1`。面积必须严格小于当前 28,060.998081 µm² 的 110%，即 **30,867.097889 µm²**；六程序 IPC 几何平均和同流程估计 Fmax 均须提高。

最终采用 **FE4、BE2、PRF56、ROB32、64 项目录**：面积 **30,330.608361 µm²（+8.09%）**，六程序 IPC **0.822319（+2.26%）**，估计 Fmax **347.118644 MHz（+3.97%）**，三项门槛同时满足。仅修改顶层 FE 和目录两个默认参数，保留前一阶段的有效位复位 PRF 实现。当前仍未达到最高档 IPC 1.0985 的联合门槛。

## 对方实现与证据

相对共同基线 `bafa464`，对方 RTL 只有一个改动：顶层默认 `STORE_DIRECTORY_ENTRIES=256` 改为 128。FE4、BE2、PRF64、ROB32、恢复宽度 7、16 项 FIFO 提示、D-Cache 16 KiB 两路等不变，没有新的目录算法或完成/写回电路可直接移植。

其 128 项方案的冻结 PPA 为面积 **32,030.126061 µm²**、估计频率 **348.062542 MHz**。面积为本轮基线的 114.14%，超过本轮上限，不能整体采用。其文档报告六程序 IPC 0.824370，明确没有做完整 correctness 或 81 组参数矩阵；这些结果不能替代本轮组合的验证。

原始综合外层报告标记 `completed=true`、`passed=false`、`sources_unchanged=false`。本轮不覆盖该失败状态：从 Git 提取对方提交，在自己的工作树重新生成同配置输入，逐一核对所有 RTL 与冻结综合输入，以及嵌入 PPA 报告的输入 SHA-256，全部一致；工具、库、框架脚本哈希也与本轮一致。因此能引用该冻结输入的 PPA 数值，但不能声称外层验收通过。独立审计在 `build/cross-deepseek-20261018/deepseek-audit/results.json`。

对方说明中的两个推断没有作为依据：

- 历史 IPC 表与已有 [256 项目录文档](store-directory-256-20261017.md) 不一致。FE2 的 128/256 项历史记录分别是 0.812045/0.815229；FE4 的实际当前比较应另列。
- 观察到某个关键路径或 ABC 映射结果，不能证明频率变化只由“路径选择”引起，也不能证明目录降容缩短了完成/写回路径。本轮只采用同配置的实际测量，不跨配置拼接频率和面积。

## 借鉴与组合

有用的思路是按实际面积预算保留少量 Store 命中证明，而不是恢复全部目录。目录只保存完整行身份和 way 所有权，不保存 Store 数据；目录别名会覆盖证明，缺少证明时仍走已有后续确认或响应路径，不把冲突当作命中。已有不可失败握手、带请求身份的后续确认、MMIO 排除、回滚和已提交写所有权均保留。

本轮在已经通过验证的有效位复位 PRF56、ROB32、BE2 基础上恢复 FE4，以减少前端供给空泡，再筛选 0、32、64 项目录。独立 Cache 默认值及组件端口不变。没有对程序、PC、地址或评测结果设置特判，也没有修改测试预期或官方综合脚本。

| FE4 / PRF56 组合 | 六程序 IPC | 相对当前 |
| --- | ---: | ---: |
| 无目录、8 项提示 | 0.816148 | +1.49% |
| 32 项目录 | 0.818505 | +1.78% |
| 64 项目录 | 0.822319 | +2.25% |

无目录组合的同配置综合为 28,643.294121 µm²、325.079365 MHz；IPC 虽提高，频率下降，不采用。参数容量与估计频率没有单调关系，其他组合必须独立综合。

64 项组合通过面积和频率门槛后停止继续综合，32 项组合只保留六程序筛选证据，不声称它已通过 PPA，也不声称本轮枚举了全局最优配置。

## 验证边界与复现

所有候选使用独立冻结源、配置、输入哈希和官方原版模拟器；筛选只跑六个 `perf_*`。综合按顺序运行，使用同一 Yosys 0.63、ABC、ASAP7 RVT TT、FakeRAM、OpenSTA `opt`，目标周期 2 ns、INVx1 驱动、5 fF 负载。频率是理想时钟、无互连寄生的综合估计。

四路前端、PRF56、恢复宽度 7 的核心已用三个随机种子逐退休对照。其冻结核心 RTL 在三个目录候选之间逐文件相同，Cache 不在该直接核心测试内，不能把它当作 Cache 集成验收。

最终 25 项官方程序全部通过，六项性能与筛选逐周期一致；Verilog-2005、启动检查、严格 Verilator lint 均通过。本轮不重复 `make unit` 或完整 81 组参数矩阵：`41752dc` 的完整矩阵报告仍是 `completed=true`、`passed=true`、`sources_unchanged=true`，本轮重新核对其所有非顶层依赖哈希不变，顶层只改两个参数默认值。核心和组件代码证据可复用；由于 Cache 目录配置改变，先前矩阵不能称为新配置的全矩阵验收。

64 项目录的定向检查覆盖 512 set、两路下的目录身份与别名；该组件测试使用默认单 MSHR，其他测试覆盖随机读写、四个种子的 HUM/后续确认、已提交写跨回滚及 flush。另有双 MSHR、带标签返回、后续确认与 AUX 组合的三个延迟/种子配置，每项检查 647 个响应，均观察到同线合并、双 MSHR 活跃、同时返回和 6 次注入错误，全部通过。真实顶层的双 MSHR 集成另由选定程序集检查。

补充工具的两次失败保留在 `focused-failed-*`：一次是对省略空端口的综合投影执行严格 lint 导致 PINMISSING，随后改为检查原始冻结 RTL 并显式覆盖参数；另一次是把仅为“强制后续确认”刺激设计的 LSQ 测试用在可直接证明命中的大目录上，测试要求 `confirm_valid`，而实际更早给出合法 irrevocable 握手。后者改用该测试的原有即时证明模式，后续确认另由目录/HUM 测试覆盖。未修改 RTL 或放宽测试断言。

构建与证据位于 `build/cross-deepseek-20261018/`；驱动在 [experiments/cross_deepseek_20261018](../experiments/cross_deepseek_20261018/)，复用此前冻结测量工具，例如：

```sh
python3 -B experiments/area_20261018/measure.py --phase prepare \
  --out build/cross-deepseek-20261018/fe4-d64-h8 \
  --fe 4 --phys 56 --rob 32 --directory 64 --hints 8
python3 -B experiments/area_20261018/measure.py --phase screen \
  --out build/cross-deepseek-20261018/fe4-d64-h8
python3 -B experiments/area_20261018/measure.py --phase ppa \
  --out build/cross-deepseek-20261018/fe4-d64-h8
```

`prepare` 要求输出目录不存在，重复实验应使用新目录。所有运行均有 timeout；不覆盖既有失败证据，不改对方分支，不修改 SORA，不推送。

完整程序、PPA、补充验证及门槛检查结果见 [机器可读汇总](../experiments/cross_deepseek_20261018/results-summary.json)。`finalize.py` 重新计算六程序 IPC，核对同流程工具/库/约束、冻结依赖与日志哈希，并重新生成待提交默认配置，逐文件核对测量输入；汇总 `completed=true`、`passed=true`。
