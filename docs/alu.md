# RV32I 整数算术逻辑单元

## 功能

`rv32i_alu` 是单发射、单周期的整数与控制流执行单元。模块支持 RV32I 的寄存器和立即数算术、逻辑、移位、比较、LUI、AUIPC、条件分支、JAL 与 JALR。乘除法、访存地址生成、FENCE、SYSTEM 和 HALT 不进入本模块。

多发射后端为每个整数执行端口实例化一个相同的 ALU。默认 ROB tag 宽度为 5 位，也可通过 `ROB_TAG_WIDTH` 参数调整。ALU 在响应中原样返回请求的 ROB tag，供完成网络定位 ROB 项。

## 内部结构

模块由组合计算逻辑和单项响应寄存器组成。组合逻辑根据 `request_op_i` 同时计算写回值、控制流有效位、taken 状态和实际下一 PC；响应寄存器在请求握手的上升沿保存这些结果。

加减法、PC 相对目标和链接地址均按 32 位自然回绕。SLT、SLTI、BLT 和 BGE 显式采用 32 位有符号比较，其余对应指令采用无符号比较。寄存器移位和立即数移位只使用移位量低 5 位，算术右移保持符号位。JALR 使用 `rs1 + immediate` 作为目标，并强制清除最低位。

非控制流指令将 `response_control_valid_o`、`response_control_taken_o` 和 `response_next_pc_o` 置零。条件分支不写寄存器，因此 `response_value_o` 为零；未跳转分支的实际下一 PC 为 `pc + 4`。JAL 和 JALR 返回 `pc + 4` 作为链接值，并始终报告 taken。

## 时序与握手

请求在 `request_valid_i && request_ready_o` 成立的上升沿被接收，结果在该上升沿之后通过 response 接口有效。消费者在下一上升沿完成响应握手，因此执行延迟为一个周期。

响应寄存器为空或当前响应将在本周期被消费时，`request_ready_o` 为高。这允许同一上升沿消费旧响应并装入新结果，在无回压时达到每周期一条指令的吞吐率。若 `response_ready_i` 为低，模块保持响应的所有字段稳定并停止接收新请求。

`reset_i` 是高有效同步复位。顺序状态的优先级为 reset、flush、接收请求、消费响应、保持。reset 或 flush 为高时，请求和响应握手立即被屏蔽；对应上升沿清空响应有效位和数据寄存器。模块不在下降沿修改任何状态。

## 接线

整数保留站连接 request 接口，并在握手成功后释放对应表项。完成仲裁网络连接 response 接口；仲裁未授权时将 `response_ready_i` 保持为低，使结果留在 ALU 内。ROB 和物理寄存器文件不直接连接请求侧，而是在完成网络接受响应后根据 ROB tag 更新状态和写回结果。

译码器必须只把 INT、BRANCH 和 JUMP 类中的受支持操作发往本模块。其他操作码不属于 ALU 接口契约；组合逻辑仍为其提供确定的全零默认输出，避免锁存器和未知值。
