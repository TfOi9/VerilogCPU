# 100 分性能优化与验证

## 目标与当前边界

从本地 main `138881b` 出发，在 `codex/tier3-performance-20261019` 中实现。100 分要求同一配置完成正确性验收，且六项官方性能程序 IPC 几何平均至少1.0985、官方综合面积至多36000 µm²、估计频率至少300 MHz。结果尚在资格验证中，不能把单项通过写成100分达标。

当前分支候选配置为FE4/BE4、PRF64、ROB32、LSQ8、64项Load值缓冲、64行SRAM取指缓冲、四MSHR与四项桥接读队列；I-Cache为1 KiB单路，D-Cache为16 KiB双路、每路四bank，Store hints为8，directory关闭，流式预取距离为4行。外存延迟固定10周期，L1 Cache三周期命中契约保持。

## LSQ值复用与数据字段共享

Load值缓冲按物理字地址索引，使用低位和相邻高位异或；每项保存完整字地址标签、32位数据与valid。只有成功且归属有效的完整字Load返回能填充，字节或半字Load返回不能填入未被该访问证明的其他字节。相关Store地址握手和Cache写请求接受时失效；真正退休的普通RAM Store可按字节更新已有项，完整字Store可建立新项。现有提交协议只允许槽0的Store退休，因此缓冲只建立这一条退休写口，不复制其余提交槽的数据读取网络。MMIO和异常Store不填入。

AGU命中必须通过完整ROB/LSQ身份、地址合法性和所有较老Store的依赖检查。选中值先保存在对应LSQ项的既有data_valid/store_data字段中，字段含义由Load/Store类型区分；因此没有额外建立每项32位暂存器。Cache请求选择排除这些已有快照的Load，完成仍通过原有仲裁和回压寄存器，回滚及重分配保留代际检查。

值缓冲只复位valid；每次建立有效项都同时写入完整标签和数据。未初始化payload不能在valid之外使用。失效和填充同拍时排除相关Store冲突，迟到、取消和错误响应不填入。

## 空闲流式预取与MSHR

四项流跟踪表识别连续行；仅在没有外部需求请求且Cache入口空闲时，尝试下一目标行。预取经过同一SRAM流水线。命中直接丢弃；重复或没有可用MSHR的预取可以丢弃，不产生核心结果。

预取MSHR允许零等待者。需求请求合并后将其变成普通所有者，并维护实际等待队列；空预取完成只填Cache，错误不安装新行也不向核心伪造响应。脏牺牲行写回失败时保留原行和脏数据，后续需求可正常重试。需求请求、MSHR槽、ROB标签、返回ID和读写响应分别保持归属。

MSHR与桥接读队列支持2/4项；Cache至桥接的ID宽度按实际启用的MSHR数计算，阻塞或关闭HUM时保持单项宽度。桥接保存每笔读的所有者和完整ID，AXI读返回按原顺序归还，写响应保留独立归属。MMIO到达时停止新预取，排空Cache后才交给桥接；MMIO在途期间继续禁止预取。

## SRAM取指缓冲

原有取指行缓冲可选同步SRAM保存128位行数据，标签和valid仍使用寄存器。局部请求读出后使用原有本地响应valid/PC；反压期间持续重读被持有的行，避免FakeRAM空闲输出未定义。填入优先于新的局部读，错误行不填入，重定向清除在途本地响应。它位于L1之外，不改变L1命中契约。

## 验证入口

`tools/test_tier3_paths.py`覆盖多MSHR归属、四笔读桥接、预取合并/空完成/读错误/脏牺牲行写回错误，以及SRAM取指反压和重定向，包含错误ID及伪造预取响应的负对照。`tools/test_load_values.py`用独立架构解释器检查90组合法Load/Store竞态；去掉完整字填充限制的负对照必须产生结果不匹配。

完整资格还要求unit/lint/HUM、81配置矩阵、25项官方程序、选定可选结构的顺序/乱序逐退休差分，以及同冻结快照PPA。命令、退出状态、输入和日志SHA256由`experiments/tier3_20261019`工具保存。初次墙钟超时、位宽失败及其他被拒绝候选保留，不能作为通过证据。
