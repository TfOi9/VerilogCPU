# 参数化物理寄存器文件

## 功能

`rv32_physical_register_file` 保存 RV32 乱序后端的物理寄存器数据。模块按 `BE_WIDTH` 提供两倍数量的读端口和相同数量的写端口：每条后端指令最多同时读取两个源操作数，每个写回 lane 最多更新一个物理寄存器。所有跨模块数组均压平成 packed bus，lane 0 位于总线最低位。

`PHYS_REGS` 指定物理寄存器数量，`PHYS_REG_ADDR_WIDTH` 必须是能够表示最后一个物理寄存器编号的最小宽度。因此模块既支持 64 项配置，也支持 48 和 96 等非二次幂配置。可编码但超出实际容量的地址不会访问内部数组：读取返回零，写入被忽略。

物理寄存器 0 是固定零寄存器。它的所有读取均返回零，所有直接写入和旁路写入均无效。PRF 只保存数据，不保存源操作数的 ready 或 busy 状态；后续重命名和记分牌逻辑负责跟踪数据是否可用。

## 内部结构

数据阵列由 `PHYS_REGS` 个 32 位寄存器组成。读端口是组合逻辑，先读取当前阵列值，再按写端口编号从低到高检查同周期写回。如果多个有效写端口命中同一非零地址，最高编号 lane 的数据覆盖之前的结果。正常 CPU 不应产生重复目的物理寄存器，但固定优先级保证异常输入仍有确定结果。

写回旁路使重命名或 dispatch 逻辑能够在写回上升沿所在周期直接获得新值，不必额外等待一个周期。旁路不会提前修改阵列，只影响组合读输出。

## 时序与复位

内部阵列只能在 `clk_i` 上升沿更新。`reset_i` 是同步高有效复位，优先于全部写端口；reset 为高时组合读输出也立即屏蔽为零，并在随后的上升沿清零整个阵列。正常周期中，有效、非零且未越界的写地址在上升沿落盘，没有写入的表项保持原值。

同地址多写的阵列更新和读旁路使用相同的最高 lane 优先级。物理寄存器 0 在每个正常上升沿被再次固定为零。分支恢复不需要清空 PRF，因此模块没有 flush 端口；恢复后的映射表和空闲表会让年轻指令留下的旧数据不可达。

## 接线

后续 decode/rename/dispatch 流水将每个 backend lane 的两个源物理寄存器编号连接到读地址总线，并把读值送入相应保留站。完成仲裁网络把最多 `BE_WIDTH` 路写回的 valid、目的物理寄存器编号和值连接到写端口。写回网络必须保证正常执行时不同 lane 不会同时写同一个目的物理寄存器。

参数检查在仿真开始时拒绝非法 `BE_WIDTH`、少于 33 项的物理寄存器配置，以及过宽或过窄的地址参数。
