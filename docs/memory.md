# 固定延迟主存模型

`rv32_main_memory` 是仿真环境中的 1 MiB 主存，不属于 `cpu_core`，也不参与 Yosys 面积综合。模块内部只有一份按字节索引的数组，I 侧和 D 侧因此访问同一份程序与数据。每条缓存行占 16 字节；128 位行数据的最低 8 位对应行首地址。

## 内部结构与时序

两个端口各有一组请求寄存器、50 周期倒计时器和一组响应寄存器。I 侧只读，D 侧可读或写，并以 16 位 byte enable 控制行内每个字节。每端口最多保留一笔事务；等待响应期间及响应未被接收时，请求 ready 为低。响应 valid、数据和错误位保持到响应握手。请求在上升沿 N 被接收，响应在上升沿 N+50 后有效；D 写入在产生响应的上升沿生效。

两端口的倒计时互不阻塞。如果 D 写入与 I 读取同一行恰好在同一上升沿完成，I 读取会看到此次写入的有效字节及其余原有字节。D 写响应仅表示写入完成，读数据为零。复位清除待处理请求和响应，取消尚未完成的写入，但不会擦除已经写入的字节。

## 地址、镜像和错误

端口地址均为 32 位字节地址，必须 16 字节对齐。有效行首地址为 `0x00000000` 至 `0x000ffff0`。未对齐或越界请求在同样的 50 周期后返回 error；读数据为零，写入不改变内存。

仿真开始时整个数组清零。通过 `+MEM_IMAGE=<path>` 可将现有 `.image` 稀疏字节镜像加载到数组；`@` 标记的是字节地址，未列出的地址保持为零。未给出镜像参数时，全零内容可供独立单元测试使用。

## 接线与验证

后续 I-Cache 的 refill 请求连接 I 侧 ready/valid 行读取接口；D-Cache 的 refill 与脏行回写连接 D 侧 ready/valid 读写接口，回写时提供 128 位数据和逐字节写使能。两个 Cache 共享同一主存实例；LSQ 仍通过 D-Cache 的 32 位字接口访问数据，不直接连接主存。主存错误由 Cache 传递给访存路径。

`make main-memory-lint` 检查 Verilog 2005 语法，`make main-memory-unit` 检查固定延迟、回压、双端口、读写可见性、地址错误、复位及实际生成镜像的加载。两者也分别接入 `make lint` 和 `make unit`。
