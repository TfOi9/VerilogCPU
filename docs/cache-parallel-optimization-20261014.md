## 改动与安全边界

- 单项脏行写回缓冲允许写回与 refill 重叠；原 miss 等待两者错误归属完成，再安装新行。写回失败保留旧脏行。
- 一个 demand miss 上下文允许其他组 hit-under-miss；缺失组锁定，SRAM 安装及重读快照时暂停流水。第二个 D miss 仍会阻塞。
- 桥接器支持两个读行和一个写行，各 AXI 字通道独立推进。两个读行可属于 I/D 不同客户端，不代表 D-Cache 有两个 MSHR。MMIO 等旧事务排空。
- LSQ 四项请求使用独立 ID；Cache/MMIO 返回原 ROB 标签，早 Load 返回保存访问属性，保留核心的 ROB 存活和代际授权。满载同拍 ID 回收/发出避免额外空泡。
- Cache 响应使用头部加 skid 槽，隔离上游反压组合路径，保持三周期无阻塞命中。

还修复了基线中潜伏的完整标签回绕问题：延迟的已退休 posted Store 响应可能与复用槽的新 Store 标签完全相同，错误地使新 Store 可退休。退休旁路和响应回写现均排除已退休写，旧响应只排空，不能授权复用槽。定向用例在旧基线失败，在最终版本通过。

结构、接线及不变量见[元件文档](/Users/zhaoruicheng/Downloads/VerilogCPU/docs/cache-hit-under-miss.md)。

## 验收与剩余瓶颈

最终源码通过：`make unit`、`make lint`、`make deep-unit`；28 项并行访存定向检查（包括错误标签注入的预期拒绝）；3 项既有契约负向检查；81 组参数的324项静态检查、9组代表配置的243次程序运行与27次退休轨迹差分；选定大 Cache 配置的25项官方程序。六项官方性能周期与带计数器的仿真一致。

v7 与较早阶段的中止/失败运行保留在原目录，未计入最终验收。最终 RTL 与 v6 PPA 输入原始快照逐字节一致，复用了该已完成 PPA；新的完整回归针对最终快照重跑。源文件、模拟器、输入、结果、日志及最终报告哈希经 `report.py` 审核。

距离最高档仍需 **61.16%** IPC 提升和 **3.89%** 频率提升，面积余量 **2,970.84 µm²**。

- 单个 demand miss 和同组锁定仍限制访存重叠；接下来应比较关键字优先返回、第二项 MSHR 和同一行请求合并，保持错误归属。
- rsort 仍有43.53%的总周期等待队首 Store 响应，vvadd 为56.57%。本轮没有减少 refill 数量，流式访问仍需预取、整行写合并或免读分配的独立证据。
- qsort 的队首 Load 等待约29.87%、恢复约15.11%；依赖传递与条件分支解析仍需优化。上述类别以总周期为分母，属于无退休周期的互斥分类。
- 继续约束返回广播、标签授权及请求选择组合路径；本轮没有可靠地把映射后的最长路径反查到某一 RTL 模块，不能声称已经定位最终关键路径。
