# RV32M 三级流水乘法器

## 功能

`rv32m_multiplier` 是单发射、完全流水化的 RV32M 乘法执行单元，支持 `MUL`、`MULH`、`MULHSU` 和 `MULHU`。模块采用 radix-4 Booth 编码、Wallace Tree 压缩和最终进位传播加法。无回压时延迟为三个周期，流水线填满后每周期可以接收并完成一条请求。

接口通过 `ROB_TAG_WIDTH` 参数配置 ROB tag 宽度。请求携带操作码、两个 32 位操作数和 ROB tag，响应返回对应的 32 位结果及原 tag。后续 MUL 保留站在请求握手后释放表项，完成网络通过响应接口施加回压并接收结果。

## Booth 部分积

两个输入先根据操作类型扩展到 33 位。`MULH` 对两端进行符号扩展，`MULHSU` 仅对左端进行符号扩展，`MULHU` 和 `MUL` 对两端进行零扩展。`MUL` 只使用积的低 32 位，因此零扩展不会改变结果。

右操作数作为 Booth 乘数。编码器在最低位之后补一个零，并在 33 位乘数之上复制符号位，形成 17 个 radix-4 编码组。每组选择 `0`、`+X`、`+2X`、`-X` 或 `-2X`，再按照组号左移。部分积统一扩展为 66 位，能够容纳符号取反、最高无符号位以及压缩过程中的保护位。

最低编码组的隐含低位固定为零，最高编码组受符号扩展约束，所以边界组只有部分三位编码可达；中间编码组可以覆盖全部八种编码。

## Wallace Tree

第一级寄存 17 个 Booth 部分积以及高低位选择、操作有效标志和 ROB tag。第二级组合逻辑使用 15 个 66 位 3:2 CSA，将操作数按以下层次压缩：

```text
17 -> 12 -> 8 -> 6 -> 4 -> 3 -> 2
```

每个 CSA 的 sum 行使用逐位异或生成，carry 行使用逐位多数逻辑生成后左移一位。压缩阶段不传播进位，也不使用行为级乘法。第二级寄存最终两行及随流水携带的控制信息。

第三级使用一次 66 位进位传播加法得到最终积。`MUL` 选择 `[31:0]`，其余三种指令选择 `[63:32]`。不属于乘法器契约的操作码会产生确定的零结果，同时保持请求的 ROB tag。

## 时序与握手

请求在 `request_valid_i && request_ready_o` 成立的上升沿进入第一级。无回压时，它在第三个有效上升沿后出现在响应端；连续请求会在此后每个上升沿产生一个响应。所有顺序状态仅在时钟上升沿使用非阻塞赋值更新。

三级寄存器均具有独立 valid，并通过 ready 从响应端向请求端反向传播。某一级为空或能够在本周期向下一级移动时，它可以接收新内容。响应被阻塞时，输出 value 和 tag 保持不变；内部可以继续填充剩余空槽，三级全部占满后请求 ready 拉低。回压可能延长请求的交付时间，但不会改变顺序或结果。

`reset_i` 是同步高有效复位，状态优先级为 reset、flush、正常流水移动。reset 或 flush 为高时，请求 ready 和响应 valid 立即被屏蔽，对应上升沿清除全部 valid 和 payload。flush 会杀死所有尚未交付的乘法请求，解除后流水线可以立即接收新请求。

## 接线

MUL 保留站连接请求端，并仅发送四种 RV32M 乘法操作。完成仲裁网络连接响应端；仲裁未授权时将 `response_ready_i` 保持为低。乘法器自身不写物理寄存器或 ROB，完成网络接受响应后根据返回的 ROB tag 执行写回和完成标记。
