# Load/Store Queue

`rv32_load_store_queue` 保存未完成的访存指令。默认 8 项，每项记录完整 ROB tag、类型、宽度、无符号标志、地址、store 数据、执行和提交状态。LSQ tag 默认由 3 位槽索引及 2 位 generation 构成；槽位复用时 generation 递增，所有地址、数据与回滚输入同时核对 ROB tag 和完整 LSQ tag。分配按 dispatch lane 顺序选择空槽，并对整个 bundle 原子接收；本周期释放的槽不立即借给新分配。

## 访存顺序与转发

两路保留站可以同时提出地址，但 LSQ 每周期只接收一条，优先接收相对 ROB head 更老的指令。store 地址和数据分别到达，只有两者齐备才报告执行完成。load 必须等待全部更老 store 的地址已知，然后逐字节找覆盖该字节的最近更老 store。若所有请求字节都有就绪的 store 数据，直接拼接并按 LB/LBU/LH/LHU/LW 扩展；只覆盖部分字节时等待相应 store 退休；无重叠时读取缓存。地址已知但 store 数据未就绪时，同样阻塞有关 load。

地址按自然对齐和 1 MiB 范围检查。非对齐和越界分别生成 RISC-V load/store 地址异常（原因 4/6 和 5/7），`tval` 为有效地址，不发缓存请求。缓存读错误生成原因 5。写错误发生在 store 首次报告执行完成以后，因此 LSQ 再发出一次带原因 7 的完成；ROB 接受该 store 的晚到异常后，LSQ 才允许它退休。

## 缓存与提交

缓存端口一次只保留一笔事务。请求寄存器在回压期间保持地址、写数据和 byte enable；读写地址是对齐的 32 位字地址，写数据按字节偏移移位。读响应提取目标字节或半字并送入单项完成缓冲，该缓冲与其他执行来源一样接完成仲裁网络。

store 首次完成后仍留在 LSQ。只有它成为 ROB lane 0 的提交候选，才生成缓存写；写响应成功后拉高对应 `commit_ready_o`，在 `commit_fire_i` 时释放。异常 store 无缓存写，ROB 保存异常后可直接提交。LSQ 根据 ROB 提交操作码识别 store；缺少匹配表项时保持回压并在仿真中报告协议错误。其余提交 lane 保持正常就绪；非 lane 0 的 store 等成为 head 后再写入。这样任何 store 写入都位于所有更老指令完成之后。

选择性恢复阻止新请求和完成握手，并按完整 tag 删除错误路径项。已发出的 load 请求被标记为待丢弃，缓存响应在恢复结束后排空，不污染复用槽。缓存响应在恢复周期受回压。全局 flush 清空本地状态；系统集成时不得把它用于取消已经交给缓存的架构 store 写。

## 接线与验证

LSQ 分配端连接 dispatch、ROB 返回的分配 tag 与译码器的宽度/符号属性；地址和 store 数据端连接两个访存保留站。完成端作为现有完成仲裁网络新增的一个来源，异常字段直达 ROB。ROB 的提交候选、提交 fire 和异常字段连接 LSQ 的提交端口；ROB 回滚 tag 接 LSQ 的选择性删除端口。后续 D-Cache 按文档中的 ready/valid 字请求和响应接口连接。

定向测试覆盖未知 store 地址、逐字节转发、部分覆盖等待、不同宽度与符号扩展、缓存延迟/回压、写错误、非对齐/越界、tag 复用和回滚。另有 LSQ、真实完成网络与 ROB 的集成测试，核对 load 写回以及晚到 store 异常。
