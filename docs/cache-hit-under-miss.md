# D-Cache 命中越过缺失与跨行 AXI 桥接

本轮第一阶段保留一个 demand miss，上游最多四笔在途；实现命中越过缺失、单项脏行写回缓冲，以及桥接器两个读行和一个写行并行。尚未实现多项 D-Cache MSHR 或同一行缺失合并。性能及最终 PPA 见本轮实验报告。

## Cache 内部结构与访问顺序

命中继续经过 s0 地址、s1 SRAM/标签读取、s2 命中与写合并，保持三周期无阻塞命中延迟。miss 发生时把地址、写数据、字节掩码、响应 ID、完整 ROB 标签和替换信息复制到独立上下文，释放 s2。其他组的命中可继续推进；第二个 miss 会停在 s2 等待。

缺失组在事务完成前锁定，覆盖所有路。新请求不能进入该组，已进入 s1 的同组请求也暂停。refill 写 SRAM 时暂停命中流水的读写，随后通过 REPLAY 重读 s1 的标签、有效位、脏位和数据，防止使用安装前的快照。已有整行 Store 旁路继续处理相邻部分字节写。

脏 victim 的地址和128位数据保留在单项写回缓冲，写请求接收后即可发送 refill，二者分别记录 sent、done、error。仅在两者均完成且无错误时安装新行；原请求在两者错误结果均已确认后才生成响应。写回成功但 refill 失败时保留旧行并清除其脏位；写回失败时保留旧行与脏数据。不同组命中不会触碰 victim。

两个响应寄存槽由头部响应与可选 skid 槽构成。无反压时 s2 直接在第三拍填入头部；反压时再容纳一项。流水就绪只取决于 skid 槽的注册有效位，消除上游写回反压贯穿 Cache 请求就绪和 Store 提交的组合链。满队列释放后的恢复允许一个周转空泡，以换取组合通路隔离。响应 payload 在握手前保持不变。

## LSQ 请求关联

`TAGGED_RESPONSES` 模式使用四项在途表。两位请求 ID 标识表项，每项同时保存完整 ROB 标签、LSQ 代际标签、原始字节地址、访问宽度、符号扩展属性和请求类型。Cache 将 ID 随 s0/s1/s2 或 miss 上下文传递，响应可以换序。`ECHO_ROB_TAG` 让 Cache 原样返回完整 ROB 标签，减少早广播前的串行查表；MMIO 也独立保存和返回该标签。

`FAST_RETURN` 使用已接收请求表中的有效位、discard、访问宽度及符号属性处理返回值。其不变量是：未退休、未取消的 Load 或普通 Store 在响应到达前一直拥有原 LSQ 表项；回滚必须将所有已接收的年轻请求标记 discard；已退休 posted Store 不再更新 LSQ 槽。仿真断言继续检查完整 LSQ/ROB 身份、响应标签一致性与 ID 有效性，核心的 ROB 存活及代际授权检查保留。关闭该参数则沿用 LSQ 身份查表路径。

ID 在响应握手前不能复用。满队列同拍回收和发出时，新请求借用本拍释放的 ID；若新请求被 Cache 反压，寄存该 ID 以保持后续有效负载稳定。尚未发出的请求可以预先准备，避免满载周转时再增加请求准备空泡。

回滚标记已接收的年轻请求为 discard，继续接收并排空其响应。旧代际响应不能更新复用槽。已退休 Store 的 Cache 写所有权继续保留；提前退休仍只允许 Cache 保证不可失败的驻留 RAM Store。MMIO 等所有前序 RAM 请求排空，独立保存请求 ID 和 ROB 标签，等待自身响应后退休。

本轮还修复了原基线中的完整标签回绕问题：延迟的已退休 posted Store 响应可能恰好与复用槽的新 Store 拥有相同 ROB/LSQ 标签。退休就绪旁路和响应回写均明确排除 `pending_posted`，不能依靠有限位宽代际相等来授权新 Store。posted 写返回错误仍触发契约断言。

## 桥接器

`PARALLEL` 模式的 arbiter 保存两个读行的 FIFO 所有者和一个写行所有者。I/D 读请求共享读队列，D 写回使用写槽；MMIO 必须等所有旧事务响应被上游接收后进入，且只发送一个字。

adapter 的 AR/R 和 AW/W/B 独立推进。两个读行最多发出八个字地址；R 按 AXI4-Lite 有序响应分别组装两个128位行。写槽独立流水发出四个 AW 和 W，只有已配对的地址与数据才能消费 B。响应错误粘滞保存，整行字事务全部排空后才返回一次响应。

完成响应携带 read/write 类型，由 arbiter 分发给原客户端。被反压的响应锁定类型和 payload，不能被后来完成的另一通道覆盖。共享复位取消桥接器及从设备的旧请求/响应；不支持仅复位桥接器而保留从设备旧事务。

## 接线与参数

- `student_top.NONBLOCKING_DCACHE` 控制 Cache 与 LSQ 标签模式。
- `PARALLEL_BRIDGE` 控制跨行桥接；`HIT_UNDER_MISS` 可独立关闭命中越过缺失，保留写回/refill 重叠，用于消融。
- Cache 的 `memory_response_write_i` 关联写回与 refill 响应。
- `core.dcache_request_id_o`、`dcache_response_id_i` 与 Cache 的 ID 端口连接；MMIO ID 由顶层独立寄存。
- `core.dcache_request_rob_tag_o`、`dcache_response_rob_tag_i` 与 Cache 的 ROB 标签端口连接，宽度由 ROB 容量推导。
- `FAST_MEMORY_RETURNS` 控制 LSQ 的返回属性快路径；关闭后保留并行 Cache 和完整身份查表。
- 独立 Cache、LSQ、core、bridge 默认保留兼容模式，旧的有序内存模型无需支持换序响应。

## 验证

`make hum-unit` 验证1/2路 Cache 的命中越过缺失、同组锁定、脏行保护、读/写错误两种完成顺序、部分字节写、响应反压和三周期命中；验证桥接器两个读行加一个写行并发、八字在途、独立 AW/W、错误归属、响应锁定、MMIO 排空和在途共享复位。

LSQ 专项检查逆序响应、回滚、同槽代际复用、精确 Load 错误、完整标签回绕后的旧 posted 响应，以及错误 ROB 标签注入后拒绝响应。三个宽度/容量代表配置、三个随机种子使用独立架构解释器的退休轨迹核对，内存模型支持四笔在途、换序响应和已提交写。完整参数矩阵与官方 Cache 集成程序另外运行，所有命令均设 timeout。
