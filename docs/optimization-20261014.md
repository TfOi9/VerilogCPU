# 分支恢复与仲裁树集成（2026-10-14）

本轮把 INT/MDU RS、完成写回的树化仲裁集成到正式 RTL，并把恢复宽度独立为 `RECOVERY_WIDTH`，整核默认值为 4。Store 提前准备的两个候选在综合程序上没有稳定收益，未集成。Cache 默认配置不变。

比较基线是 `74cd2d8`，不是早期的隔离 PPA。所有性能结果均固定 FE=BE=2、PRF64、ROB32、外存延迟 10 周期。默认 Cache 为 I 1 KiB / D 4 KiB、直接映射；大 Cache 为 I 2 KiB / D 16 KiB、D 两路。六项 IPC 按测试集动态指令数除以程序总周期计算，并取几何平均。

## 实现与边界

`rv32_ranked_select` 并行计算候选之前的有效项数，以平衡加法树与数据 OR 树代替串行选择链；年龄相同时按槽号稳定排序。INT 和 MDU RS 的当拍发射槽位下一拍才能重新分配，切断发射选择到 dispatch ready 的路径。写回仍遵守原轮转顺序和反压语义。结构与接线见 [ranked_select.md](ranked_select.md)、[int_rs.md](int_rs.md)、[writeback.md](writeback.md)。

ROB 每拍最多回滚 4 项，回滚总线贯穿 Rename、各 RS 和 LSQ。回滚顺序保持从年轻到年老；同批多次修改同一架构寄存器时，较老项恢复的映射最终生效。LSQ 同时取消驻留项并标记已经发出的错误路径请求，避免旧响应误写新项。组件单独实例化时仍默认 `RECOVERY_WIDTH=BE_WIDTH`，整核和顶层默认 4。恢复仍暂停正常完成与后端推进；本轮没有引入重命名检查点或恢复期间的较老指令继续执行。见 [rob.md](rob.md)、[rename.md](rename.md)。

## 六项程序结果

| 程序 | 默认 Cache 基线周期 | 默认 Cache 优化周期 | 大 Cache 基线周期 | 大 Cache 优化周期 |
| --- | ---: | ---: | ---: | ---: |
| median | 19,118 | 17,794 | 17,966 | 16,642 |
| multiply | 23,886 | 23,823 | 23,886 | 23,823 |
| qsort | 394,385 | 369,404 | 293,827 | 267,606 |
| rsort | 691,854 | 691,847 | 299,325 | 299,317 |
| towers | 12,076 | 11,999 | 12,054 | 11,977 |
| vvadd | 10,691 | 10,691 | 9,629 | 9,629 |
| **六项 IPC 几何平均** | **0.427982** | **0.438542** | **0.531592** | **0.547700** |

默认 Cache 的均值提升 2.47%，大 Cache 提升 3.03%。大 Cache 下 qsort 吞吐提高 9.80%，median 提高 7.96%。仅仲裁树集成时，multiply/qsort/rsort 在两种 Cache 下周期均与基线相同；本轮可见的 IPC 收益主要来自恢复加宽。

大 Cache 的 qsort 恢复事件数为 10,772 → 10,766，回滚项数为 166,114 → 156,294，恢复周期为 85,811 → 42,774，每次平均恢复长度为 7.966 → 3.973 周期。这证明本次主要缩短了恢复，并不表示预测器准确率提高；执行完成事件仍可能属于之后被取消的推测路径。

实验计数器分别记录执行端控制流完成/预测不符、前端返回时的路径修正、恢复长度和回滚深度直方图。`load_candidate_with_inflight` 只表示候选 Load 与在途请求同时存在；请求反压和在途队列满另行记录，不把前者计为真正阻塞。互斥退休分类、退休数量与直方图加权和均自动核对。

## Store 候选的取舍

两个候选都只提前准备下一笔普通 Store 的请求，仍在所有较老项真实成功退休后发出，不提前确认可能失败的 Store，MMIO 仍限制在队首。第二版还允许尚不能发出的 Store 暂时让位给已就绪 Load。

| 候选 | 热 Store 周期 | 大 Cache qsort 周期 | 大 Cache rsort 周期 |
| --- | ---: | ---: | ---: |
| 已集成的树化与恢复加宽 | 16,229 | 267,606 | 299,317 |
| Store 提前准备 | 13,148 | 270,802 | 298,817 |
| 提前准备并让位给 Load | 13,148 | 268,743 | 299,310 |

微基准减少了请求准备空泡，但 qsort 出现回退，rsort 收益不足以抵消它。正式 LSQ 只保留恢复总线加宽。候选补丁及错误响应、反压、取消等定向测试保存在 `experiments/optimization_20261014/`。真正解除逐笔确认仍需要明确普通 RAM Store 的错误边界与缓冲提交协议，不能用微基准收益代替综合验证。短交替分支微基准在上述各版本均为 1,964 周期，也说明浅回滚不一定受益。

## 同版本 PPA

使用同一 ASAP7 TT、FakeRAM、Yosys/ABC/OpenSTA 快速映射流程，之后进行 CEC、电容/转换时间修复和 20 ps hold 修复。三组结果均已完成：

| 版本 | 总面积 (µm²) | SRAM 面积 (µm²) | 估计频率 (MHz) | 最小 hold slack (ns) |
| --- | ---: | ---: | ---: | ---: |
| 当前基线 `74cd2d8`，默认 Cache | 25,014.49 | 1,994.04 | 187.86 | 0.020 |
| 树化 + 恢复宽度 4，默认 Cache | 24,994.60 | 1,994.04 | 300.38 | 0.020 |
| 树化 + 恢复宽度 4，大 Cache | 32,054.58 | 7,121.57 | 292.66 | 0.020 |

三组均通过修复前后逻辑等价和固定状态保持检查，最终电容、转换时间违例为零。默认 Cache 的最终最小周期估计 3.3291 ns；2 ns 约束下 setup slack 为 -1.3284 ns，因此不表示达到 500 MHz。最大扇出没有施加独立约束。时钟理想化且没有布线寄生、CTS、多角或 SDF 验证，300.38 MHz 只是该流程估计点，余量很小。

大 Cache 的最小周期为 3.4170 ns，2 ns 约束下 setup slack 为 -1.4163 ns。虽然面积低于 36,000 µm²，但估计频率低于 300 MHz；不能把它的 IPC 与默认 Cache 的 300.38 MHz 拼接为联合达标结果。

## 验证与证据

完整 `make unit`、`make lint`、45 组新增选择器/恢复宽度测试和 `make matrix-unit` 已通过。新增测试包含 21,000 次独立参考模型选择器检查、BE={1,2,4} × RECOVERY={1,2,4,8} 的 ROB/Rename 交叉验证，包括跨批回滚及同一架构寄存器重复写入的恢复。

`make unit` 的初次退出码为零，但原始日志存在三处 MDU 旧同周期复用断言失败；已更新为检查满站发射后下一拍接收，并把失败处理改为 `$stop` 配合 `vvp -N` 返回非零。重跑的 `checks/final-unit-v3.log` 包含 186 条 PASS，无 FAIL/ERROR；三组 MDU 配置分别完成 1,537 / 1,539 / 1,543 项检查和各 144 组乘除向量。`+CHECK_FAILURE` 负向控制实际返回退出码 1。旧日志不作为通过证据。

当前基线与最终 RTL 分别在默认和大 Cache 上跑完 25 个官方程序，共 100 次程序运行；每个配置覆盖全部 19 个正确性程序和全部 6 个性能程序。另有 4×4、PRF96、ROB64 的极端配置检查通过。

完整参数矩阵 `full-matrix.json` 已完成，`completed`、`passed`、`sources_unchanged` 均为 true：81 个配置的 324 项静态检查、9 个代表配置的 243 次程序运行、27 组退休差分全部通过。包括生成与构建在内的 381 个步骤全部通过；每个代表配置包含 19 个正确性程序、全部 6 个性能程序和 2 个本地 smoke。

初次全套程序沿用了三程序实验的 300 万周期上限，基线和最终版本的 `correctness_pi` 均触及上限；改用现有回归标准的 3,000 万周期上限后全部通过。初次核心 lint 在完整 `opt` 的 `OPT_MUXTREE` 阶段超过 120 秒，延长诊断运行后同配置完成且无结构错误；正式 lint 改用 `opt -fast`，保留 `proc; memory`、锁存器禁止检查，并将 `check` 加强为 `check -assert`。这些早期失败日志保留，不作为通过证据。

原始记录根目录为 `build/optimization-20261014/`，实验脚本与被拒候选在 [experiments/optimization_20261014](../experiments/optimization_20261014/README.md)，可提交结果在 [results-summary.json](../experiments/optimization_20261014/results-summary.json)。`final/source/` 冻结实测 RTL；最终汇总脚本已通过源码与证据审核，核对它与正式 RTL 的哈希，并拒绝未完成或失败的结果。

当前六项均值最高为 0.547700，离评分最高档 1.0985 仍有较大差距。大 Cache 的最终 qsort 中，队首 Store 等待响应类占 23.11%，队首 Load 未完成占 18.74%，恢复占 15.98%；rsort 的 Store 等待响应类仍占 58.64%。这里的 Store 类包括请求准备和 Cache 处理，不等同于外存等待。

后续应优先设计真正可排队的普通 Store 提交路径，继续用综合程序验证，并分别评估固定 I 容量的 D-Cache 容量/相联度收益；本轮不宣称 IPC、面积、频率联合达标。
