# Cache 定向优化与轻量验证（2026-10-14）

本轮结论：启用现成的两路 D-Cache 有收益，但扩容不足以将当前核心推进到平均 IPC 1.0。三个代表程序的几何平均 IPC 从 0.294468 提升至 0.316472（同容量两路）或 0.384672（2 KiB I / 16 KiB 两路 D）。本轮只形成可选择的优化配置与复现入口，正式 RTL 默认值保持原样；16 KiB 方案还没有整核面积和频率验收。

## 当前结构与评分目标

当前 `rtl/student_top.v` 默认参数如下；容量仅计数据，不含标签与状态。

| Cache | 数据容量 | 组数 | 路数 | 行大小 | 标签位/行 |
| --- | ---: | ---: | ---: | ---: | ---: |
| I-Cache | 1 KiB | 64 | 1 | 16 B | 22 |
| D-Cache | 4 KiB | 256 | 1 | 16 B | 20 |

两者均为同步 FakeRAM、三级命中路径、单 miss 阻塞式 Cache；D 侧使用 write-back/write-allocate。多路阵列、命中选择、优先 invalid、round-robin 替换及 dirty victim 写回已经实现，启用两路无需重写 Cache。组数必须满足 `size = sets × ways × 16`。内部结构和接线见 [dcache.md](dcache.md)、[icache.md](icache.md)。两路替换策略当前是 round-robin，不是 LRU。

本轮重新读取 `../RISC-V-CPU-2026/README-ZH.md:160` 的课程评分标准，以此为准；本仓库 `SPEC.md` 的早期面积倍率描述不能代替正式门槛。

| 档位 | 最大总面积 µm² | 全部 perf_* IPC 几何平均 | 最低频率 MHz |
| --- | ---: | ---: | ---: |
| 90 分 | 9,000 | 0.6000 | 300 |
| 95 分 | 18,000 | 0.8450 | 300 |
| 100 分 | 36,000 | 1.0985 | 300 |

因此 1.0 可作为工程里程碑，100 分实际需要 1.0985。任何三程序子集的数值都不能用于宣称评分达标。

## 实测结果

基线为 `b0ea5cef14bf78bf0ee375b0c8157bffe1c1a695` 所在工作区的正式 RTL，实际完整哈希以结构化结果为准。FE=2、BE=2、PRF=64、ROB=32；已包含正式 AXI 行内流水化，不包含前几轮隔离目录中的 LSQ 消泡、RS 切断或树化。

固定官方内存延迟 10，使用原始镜像、返回值和动态指令数。仅选择 `multiply`（前端/依赖）、`qsort`（冲突）、`rsort`（容量/Store）三个程序。串行构建，`-j 1`；构建超时 240 秒，程序超时 30 秒，周期上限 3,000,000；不开波形。有效三配置测试从本地时间 10:34:56 到 10:35:32，约 36 秒。主机耗时不是 CPU 性能指标。

| 配置 | multiply 周期 / IPC | qsort 周期 / IPC | rsort 周期 / IPC | 子集 IPC 几何平均 | 相对基线 |
| --- | --- | --- | --- | ---: | ---: |
| I 1 KiB / D 4 KiB 直接映射 | 53,503 / 0.4060 | 507,891 / 0.2755 | 857,211 / 0.2283 | 0.294468 | 1.0000× |
| I 1 KiB / D 4 KiB 两路 | 53,503 / 0.4060 | 448,846 / 0.3117 | 781,396 / 0.2505 | 0.316472 | 1.0747× |
| I 2 KiB / D 16 KiB 两路 | 53,503 / 0.4060 | 406,815 / 0.3439 | 480,070 / 0.4077 | 0.384672 | 1.3063× |

| 配置 | qsort D refill / writeback | rsort D refill / writeback | I 行读取 multiply / qsort / rsort |
| --- | ---: | ---: | --- |
| 当前基线 | 5,392 / 1,047 | 15,793 / 7,944 | 25 / 54 / 196 |
| 同容量两路 | 2,284 / 1,027 | 12,219 / 7,495 | 25 / 50 / 191 |
| 2 KiB / 16 KiB 两路 | 1,037 / 12 | 2,322 / 1,116 | 25 / 50 / 194 |

同容量两路使 qsort 加速 13.15%，映射冲突确实值得处理。大配置使 rsort 加速 78.56%，并显著减少脏行写回。大配置同时改变 I 容量和 D 容量，不能从该列单独量化 I-Cache 扩容收益。I 行请求数也受投机、flush 和 D 侧阻塞影响，不能将其差值直接解释为容量 miss 差值；三个程序尚未显示 I 扩至 2 KiB 的明确必要性。

计数器在上升沿前稳定握手点只读采样：从桥接仲裁器实际行请求区分 I refill、D refill 与 dirty writeback；队首阻塞分类互斥且覆盖全部周期。每次运行检查采样周期=官方周期=分类总和、请求间隔直方图数=请求数−1。退休数为官方动态指令数−1：官方 harness 在最后 MMIO Store 的 B 响应时结束，退休信号还未完成最后一条 Store；IPC 仍按官方动态指令数计算。

## 面积取舍

直接调用当前官方 `scripts/fakeram.py` 的 `Shape.lane_area`，按实际 data/tag SRAM 形状、byte lane 数和 ways 求和。其公式是每 bit 0.0419904 µm²；下列不含组合逻辑、valid/dirty/replacement 寄存器、缓冲和物理修复面积，不能用来代替整核综合。

| 配置 | 数据+标签 SRAM 估算 µm² | 相对基线增加 µm² |
| --- | ---: | ---: |
| I 1 KiB / D 4 KiB 直接映射 | 1,994.04 | 0 |
| I 1 KiB / D 4 KiB 两路 | 2,004.79 | 10.75 |
| I 2 KiB / D 16 KiB 两路 | 7,121.57 | 5,127.53 |

同容量两路优先作为低 SRAM 成本候选，代价还包括额外标签比较、数据选择及其时序影响。16 KiB 方案适合作为 36,000 µm² 档位的候选：扣除这些 SRAM 后，留给其余逻辑的预算为 28,878.43 µm²；这只是预算，不是面积已通过。若按 18,000 µm² 档位，则仅余 10,878.43 µm²。已有树化/电气修复报告来自不同隔离 RTL 和流程，不能直接与此 SRAM 增量相加宣称新配置合格。

本轮不跑综合、不扩大参数矩阵，不将 16 KiB 设置为正式默认。接电后的下一次 Cache 比较可加入 8 KiB 两路，以及固定 D 配置的 I 1/2 KiB 对照，并做同一整核/约束的面积和频率测量。

## 向 1.0/1.0985 IPC 推进的实际优先级

在 2 KiB / 16 KiB 两路配置下：

- `rsort` 仍有 59.80% 的全部周期被分类为无退休且队首 Store 等待响应；Load 未完成占 16.96%。所有配置的 LSQ 请求间隔众数仍是 6 周期。Cache 命中路径支持逐拍吞吐，但 `rv32_load_store_queue.v:655` 仍要求 `!request_valid && !inflight` 才准备下一笔请求。
- `qsort` 的队首 Load 未完成降至 29.44%，队首 Store 等响应仍占 27.87%。单纯消除 miss 已不能回收全部等待。
- `multiply` 周期逐项完全不变，fetch queue 空占 68.33%。`rv32_fetch_pipeline.v:462` 在返回指令中预测跳转后清空在途顺序请求并重新取目标，因此扩大 I-Cache 不能消除命中后的控制流供给空泡。

以上 fetch 空、ready load 等待等指标与队首分类有重叠，不能相加，也不能直接当成可回收周期。

建议按如下阶段推进，每次先用小测试确定因果，再接电扩大验收：

1. **Load 流水化**：先采用已隔离验证的响应当拍准备下一请求，再设计 2–4 项在途 Load 元数据 FIFO，携带 LSQ/ROB tag、generation、宽度和符号信息，按序关联 Cache 返回。保持 store alias 阻挡/转发，恢复时丢弃失效返回；用热 Load、恢复后迟到响应、完成回压测试。不能只放开 `inflight` 条件而不增加关联信息。
2. **Store 路径**：优先允许已确认的普通 RAM Store 排队推进，明确退休点、顺序、后续 Load 转发和迟到错误的精确性。结束 MMIO 必须仍到队首才发出且等待 B 响应；不能直接将所有 Store 提前退休。先用热 Store、部分字节转发、dirty eviction 错误和 MMIO 顺序小测试。
3. **前端与依赖链**：将 BTB/方向查询提前到取指地址阶段，减少正确预测 taken 的重启开销；同步检查整数结果旁路/唤醒延迟。以短分支循环、依赖 ADDI、multiply 对照，保持三周期 I-Cache 契约。
4. **最后选容量与宽度**：在以上吞吐改进后重新比较 4/8/16 KiB 两路与 1/2 KiB I-Cache，再跑六项正式几何平均和面积/300 MHz 联合门槛。当前无需先扩大 PRF、ROB 或发射宽度来掩盖串行访存。

这些是下一阶段设计方向，本轮未实现多在途 Load 或提交 Store buffer，也没有宣称达到 1.0 IPC。
