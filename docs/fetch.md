# 参数化取指流水线

`rv32_fetch_pipeline` 连接 L1 指令缓存、预译码器、分支预测器和后续 Decode 阶段。`FE_WIDTH` 控制每个缓存响应最多生成的指令数，`BE_WIDTH` 只控制预测器的提交训练端口；二者分别支持 1、2、4，可以独立配置。复位入口 PC 固定为 0，所有 packed bus 的 lane 0 都表示程序顺序中最老的指令。

## 请求与 Cache line 拆分

流水线维护下一请求 PC，并用一个固定 4 项的请求跟踪队列记录已经接受但尚未返回的 PC，以及该次请求选定的后继请求 PC。请求可以发往 I-Cache，也可以由下述取指行缓冲提供。跟踪队列允许连续四拍发出 I-Cache 请求，同时保证响应只能与最老请求配对。无匹配项或 PC 不匹配的 I-Cache 响应视为旧路径响应，直接握手丢弃，不进入 Fetch Queue。

I-Cache 每次返回包含响应 PC 的 128-bit line。流水线从 `PC[3:2]` 指定的 word 开始，最多提取 `FE_WIDTH` 条指令，但不会跨越 16-byte line。例如四路前端从 line 内偏移 `0x0c` 开始时只生成一个有效 lane，下一请求从下一条 line 开始。这样跨行取指由两个有序响应完成，不需要在 I-Cache 内拼接。

## 取指行缓冲

`FETCH_LINE_BUFFER_ENTRIES` 支持0、1、2、4，默认4，保存4条成功接受的16B指令行，共64B数据。表项直接映射，使用完整`PC[31:4]`标签、valid和128位指令数据；错误响应不填入。缓冲与L1 I-Cache位于不同层级，未改变I-Cache三周期命中的接口契约。

请求跟踪队列为空时，缓冲命中可以直接装入本地响应寄存器，下一周期进入原有预译码和Fetch Queue入队路径。只有最后一笔本地响应被接受时，才允许连续交接下一笔本地请求；存在真实I-Cache在途请求时不插入本地响应，避免越过旧请求。本地响应等待期间，I-Cache响应保持反压。已经对I-Cache呈现但尚未握手的请求被锁定，不能因为随后填入的行命中而撤回或改变PC。

连接关系为：下一PC同时查询BTB/BHT和行缓冲；命中数据经本地响应寄存器，与I-Cache返回在预译码之前选择；两者共用原请求跟踪、预测校正、队列容量检查和入队逻辑。所有本地请求也保存选择时的后继PC，返回时重新查询预测器，不能复用过期方向预测。

外部redirect或内部预测校正取消本地响应和请求跟踪，但保留已成功取回的行，帮助正确路径重启。reset清空缓冲。该规则与现有I-Cache的流水线flush保留已缓存指令行一致；缓冲不增加新的指令写入一致性保证。行标签替换不会改变已经锁存的本地响应数据。

## 预译码与预测

取指地址阶段先用候选 PC 查询共享的 BTB/BHT，按 lane 顺序选第一个有效 taken 目标作为后继请求 PC。请求握手即保存这个决定并推进目标取指，不等待当前 I-Cache 响应；未命中则按 bundle 长度顺序推进。查询不跨 16 B 行，只使用真实将返回的 lane。

返回后每个候选 lane 使用现有 `rv32im_decoder` 生成操作码和立即数，再查询同一预测器。普通指令的预测下一 PC 为 `PC+4`；条件分支、JAL 和 JALR 保存返回阶段的预测下一 PC。这一步负责验证早期 BTB 猜测，并处理冷启动与预测表在请求在途期间的变化。

流水线按 lane 顺序选择第一个预测 taken 的控制流指令，只将该 lane 及其之前的连续前缀写入 Fetch Queue。返回阶段计算的后继请求 PC 与握手时保存的值相同，就保留已经发出的目标请求，不产生内部 flush；不同则通过 `icache_flush_o` 清除更年轻请求并从修正的后继 PC 重启。误命中的 BTB、方向变化和目标变化都使用相同校正路径。预测不跳的条件分支和 BTB miss 的 JALR 不截断 bundle；执行结果不符时仍由 ROB 外部 redirect 恢复。

预测目标必须按 4 字节对齐。不对齐的预测保存 `PC+4`，继续顺序取指，不截断 bundle，也不冲刷请求；同一 bundle 中更年轻的对齐预测仍可生效。旧分支恢复以前，错误路径可能取到数据并将其译码成控制流指令，因此预测值不能直接触发取指地址断言。外部 ROB redirect 的对齐约束保持有效。

预测器训练端接收 `BE_WIDTH` 路 ROB 更新，统计端口原样导出。当前核心在 ROB 接受控制流完成时训练，可能包含后来被回滚的指令；本轮没有改为退休训练。取指冲刷不会清空 BHT、BTB 或统计；只有 reset 会重置预测器状态。

## Fetch Queue 与回压

Fetch Queue 是默认 8 项的指令级环形 FIFO，容量可通过 `FETCH_QUEUE_ENTRIES` 和 `FETCH_QUEUE_INDEX_WIDTH` 调整。容量必须是 2 的幂且不少于 `FE_WIDTH`。每项保存：

- 指令 PC；
- 原始 32-bit 指令；
- 预测下一 PC；
- I-Cache 错误标志。

输出 valid 总是从 lane 0 开始的连续前缀。后续阶段可以通过 `fetch_ready_i` 接收任意连续前缀，因此 FE 和 BE 宽度不同时不必整包消费。非连续 ready 属于协议错误。队列支持同周期多项出队和一次 Cache 响应的多项入队；响应 ready 会计入本周期出队释放的空间，因此满队列也能无气泡地完成等量替换。未被消费的最老项及其全部元数据保持稳定。

## Redirect、旧响应与错误

外部 `redirect_valid_i` 优先于请求、响应、预测和队列出队：同周期立即屏蔽前端输出，在上升沿清空 Fetch Queue 与请求跟踪队列，并从 `redirect_pc_i` 重新开始。`icache_flush_o` 同时通知 I-Cache 删除其内部旧路径事务。

预测校正只清除更年轻的请求跟踪项，不删除 Fetch Queue 中已经排在分支之前的指令。I-Cache flush 必须取消内部旧响应，包括同 PC 的旧请求；不同 PC 的迟到响应还会被跟踪队列的 PC 检查丢弃。所有正常请求和 redirect PC 必须按 4 字节对齐。

I-Cache 错误生成一个指令值为零、错误位为一的 Fetch Queue 项，并停止继续请求。该项供后续 Decode/ROB 转换为精确异常；只有 reset 或外部 redirect 会解除停止状态。

## 验证

`make fetch-lint` 对全部 9 种 FE/BE 宽度组合执行 Icarus、Verilator 和 Yosys 检查。`make fetch-unit` 覆盖顺序及跨行取指、部分消费、队列满与环回、条件分支、JAL、JALR、redirect、旧响应、Cache 错误、非法参数和协议错误，并连接真实 I-Cache 与 50 周期主存验证 miss、回填和预测冲刷。两个目标分别纳入总 `make lint` 与 `make unit`。

`make fetch-line-buffer-unit`包含1/2/4行缓冲与全部FE/BE组合共27组，检查热目标两拍重启、行内所有偏移、完整标签替换、反压保持、旧同PC错误响应隔离、失败行不缓存、JAL截断、未对齐预测降级、连续redirect及reset。关闭缓冲必须按预期拒绝热目标断言，非法3行配置也必须被拒绝。原有可改变同一PC模拟响应内容的接口单元测试显式关闭行缓冲；真实I-Cache集成与CPU回归使用默认4行。
