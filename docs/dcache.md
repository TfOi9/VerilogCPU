# 流水线 L1 数据缓存

`rv32_l1_data_cache` 是 4 KiB、直接映射、write-back/write-allocate 的数据缓存，共 256 组，每行 16 字节。`address[11:4]` 选组，`address[31:12]` 为标签，`address[3:2]` 选 32 位字。CPU 侧直接连接 LSQ 的单笔字请求和响应；读响应返回未移位的字，由 LSQ 按原访存地址完成字节提取与符号扩展。写数据和 4 位 byte enable 均对应对齐字的四个字节，写响应的数据为零。

## 命中流水线

| 上升沿 | 处理 |
| --- | --- |
| N | S0 接收请求及全部写入字段。 |
| N+1 | S1 同步读取数据、标签、valid 和 dirty。 |
| N+2 | S2 比较标签、保存查找结果；首次命中或未命中事件在此产生。 |
| N+3 | 命中读数或写确认进入响应寄存器；命中写入更新数据阵列和 dirty。 |

各级用 valid/ready 传播回压，响应未被接收时保持稳定。没有停顿或 miss 时，各级可同时处理不同请求，因此命中请求可每周期接收一笔。连续访问同组时，S2 的待写完整行同时旁路到下一项 S2 比较输入及 S1 的同周期阵列读取结果。这样同组的连续 store/store 和 store/load 保持程序请求顺序，且不依赖阵列的读写冲突模式。复位只清除 valid 和 dirty，不初始化数据与标签。

## 未命中与主存接线

单笔 miss 控制器只接管 S2 的未命中请求；S0、S1 中已经接收的年轻请求冻结。若原组有效且脏，先将 `{原标签, 组号, 4'b0}` 对应的整行以 `16'hffff` 掩码写回，收到成功确认后才从主存读取目标行；否则直接读取。写回成功时原行变为 clean。回填成功后安装新标签和数据；store miss 先把写入字节合并到回填行，并标记 dirty。原请求完成后，S1 重新读阵列，再恢复年轻请求，避免它使用回填前的过期快照。主存请求在 ready 前保持稳定，一次只允许一笔在途事务。

写回失败时保留原 dirty 行并向当前请求返回错误；回填失败时保留原行，若先前写回成功则该行保持 clean。无效、非字对齐或超出 1 MiB 范围的字请求返回错误，不访问主存，也不计入命中或未命中。有效请求在首次标签判断时恰好产生一个 `hit_event_o` 或 `miss_event_o` 脉冲，重读不重复计数。

## 与乱序后端的边界

缓存不设分支 flush 端口。LSQ 根据 ROB 提交候选才发送 store，并在需要时丢弃错误路径 load 的返回值；缓存不能取消已经接收的架构 store。脏数据立即对后续 D-Cache 读取可见，主存中的副本直到驱逐写回才更新。复位须与主存一起施加。

`make dcache-lint` 检查 Verilog 2005 语法、层次和可综合性；`make dcache-unit` 运行独立缓存测试及 LSQ—D-Cache—主存接线测试。测试包含三周期命中与逐周期吞吐、同组旁路、回压、驱逐、错误、固定种子随机一致性和 store 提交时机，并设置墙钟及仿真 watchdog。
