# Store 所有权转移与结果旁路

## RAM Store 的安全退休边界

`rv32_l1_data_cache` 默认保存 4 项驻留行提示，正式顶层选择 16 项，每项只有有效位和 28 位行地址。成功的命中与 refill 可建立提示；同组 miss 提前使提示失效，refill / 写回失败不会建立新提示。提示重复时不消耗新项。

LSQ 已完成地址、对齐、访问宽度和 RAM 范围检查，且 Store 进入 ROB 队首后，才准备写请求。Cache 对请求检查：

1. 地址合法且对齐，存在对应驻留行提示。
2. 前序 s0 / s1 / s2 中，没有同组、不同地址行的请求。
3. Cache 在 RUN 状态且能够接收请求。

这些条件成立时，`request_irrevocable_o` 表示该请求被接收后必然命中。**只有请求 valid、ready 和不可失败保证同时成立，LSQ 才允许 Store 退休。** 缺失、无法证明的冲突及 MMIO 仍走响应确认路径。保证依赖当前 Cache 命中不产生 ECC/权限错误的接口语义；未来增加这些错误时必须重新定义边界。

接收后，写请求的所有权属于 D-Cache 原有的 s0 → s1 → s2 流水线及响应寄存器。这些寄存器共同承担有限的已提交写缓冲，LSQ 的 4 项在途队列保留响应身份。此实现没有额外 SRAM 数据副本，也没有对推测 Store 提前写入 Cache。

由于 FIFO 顺序，年轻请求不能先替换已经接收 Store 的行；前序可能替换该行的请求又被同组检查排除，所以接收保证保持有效。回滚和 LSQ flush 不清除 Cache 的已接收写。退休后的 Store 响应不再更新被复用的 LSQ 项；ROB 与 LSQ 完整标签共同隔离旧响应。额外断言检查不可失败 Store 必须命中且不能返回错误。

Store 尚未退休时，Load 使用 LSQ 原有逐字节转发和部分重叠阻塞规则。退休后，同址 Load 的 Cache 请求排在 Store 后面，Cache 原有整行旁路提供最新字节，包括连续部分字节写。MMIO 只从队首请求，等待在途 RAM 请求排空并等待自身响应。

接线：`D-Cache.request_irrevocable_o` 经 `student_top` 的 MMIO 排除门连接 `core.dcache_request_irrevocable_i`，再传入 LSQ。`student_top.POSTED_STORES=1` 启用协议，`STORE_HINTS=16` 选择驻留提示项数；独立 core/LSQ 默认关闭，便于接入不提供保证的内存模型。

## 结果传递

写回网络为空的源槽允许执行单元的注册结果直接参与树形仲裁；未获得完成端口的源进入原有单项缓冲。已缓冲结果优先于同源新结果。当完成端反压时，锁住各输出选中的源，防止新到结果改变已呈现的 payload。恢复暂停传递，flush 清空有效位。

ROB 在仲裁前为每个完成源查询完整标签：活跃、代际匹配、尚未完成且写目的寄存器时，提供有效位与物理目的寄存器。缓冲源查询缓冲内标签，空源查询执行单元标签，结果不是过期的授权快照。授权与物理寄存器随数据经过同一个仲裁树；树后排除重复标签、异常、x0 与无握手结果。

ROB 的原完成接收、异常和分支处理仍运行，并由断言检查每次提前广播与其接收决定及物理目的寄存器一致。这样把标签查询从“仲裁之后再读 ROB”的串行通路移到仲裁前，与结果数据并行；没有独立的物理寄存器代际表，也不缓存跨回滚有效的授权。

Load 响应在在途队列、LSQ 标签匹配和错误检查后，可直接进入空的 LSQ 完成源；反压时捕获到原有源寄存器。旁路直接被接受时释放 Load 项，避免再发送一次结果。Cache 自身 3 周期命中延迟保持不变。

返回payload选择与旁路资格分开：空LSQ完成缓冲提前选择在途tag和值，完成valid仍核对完整身份和取消状态，错误作为完成异常传递。写回物理号和值也直接传递选定payload，由valid单独过滤授权、重复tag、异常和p0；消费者只在有效广播时使用。这两处改动减少组合资格之后的数据门控，不增加流水级，详见[返回路径时序验收](return-path-optimization-20261014.md)。

无效写回槽的 payload 保留到下一次填入，由有效位及仲裁掩码隔离，减少 reset/pop 清零的扇出。`student_top.RESULT_FALLTHROUGH` 同时控制写回与 Load 旁路，可用于独立消融实验。此通路仍包含 ROB 与 RS 的组合逻辑，频率必须以同配置综合为准。

## 验证入口

- `make deep-unit`：写回随机反压/恢复/flush、完整 payload、ROB 重复/异常/代际复用、LSQ 错误与取消、Cache 替换和部分字节随机写、已提交写跨回滚/flush。
- `make unit`：原有完整部件、退休差分与异常测试。
- `tools/run_parameter_matrix.py --all-performance`：完整参数矩阵与代表配置的官方程序。

较短的结果延迟改变了随机程序中推测异常、同时满宽写回和同时分支完成是否恰巧重叠。新版退休差分继续逐条核对架构结果；这些偶然覆盖事件在关闭旁路时保留旧断言，在开启旁路时由独立的并发/异常/代际定向测试承担。不能把某一随机轨迹未出现旧事件解释为错误，也不能把该轨迹解释为已经覆盖该事件。

该实现仍使用阻塞 D-Cache，未实现一般的提前 Store refill、独立多项 Store buffer、hit-under-miss 或 MSHR。
