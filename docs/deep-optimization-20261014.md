# Store 与结果通路深度优化：实现、回归和 PPA

**正式 RTL 已集成普通 RAM 驻留 Store 的安全所有权转移、ALU/Load 结果穿透，以及仲裁前的 ROB 标签/物理目的校验。** 最终配置 FE=BE=2、PRF64、ROB32、恢复宽度4、Store 驻留提示16项、I 1 KiB / D 16 KiB 两路、外存延迟10周期：六程序 IPC 几何平均 **0.653596**。同 Cache 的配对基线为 **0.547532**，提升 **19.37%**。

同流程配对 PPA：面积 **30,874.34 → 32,078.94 µm²**（+3.90%），估计频率 **295.87 → 295.61 MHz**。按 IPC × 估计频率折算的吞吐指标提高 **19.27%**。此值是 TT、理想时钟、无布线寄生/CTS 的估计，不能替代实际实现后的吞吐测量。

**联合目标仍未达到。** 面积满足 ≤36,000 µm²，频率还差约4.39 MHz；IPC 距1.0985仍需 **68.07%** 提升。D-Cache 需求缺失与桥接器仍然阻塞，尚未形成多行并行访存。

## 1. 正式改动

详细结构、逻辑与接线见 [元件设计](posted-stores-and-result-bypass.md)。

### 驻留 RAM Store 接收后退休

LSQ 保留地址、对齐、范围与宽度检查。D-Cache 记录成功验证的驻留行；只有地址命中提示、前序流水项不会替换该行、且请求真正被 Cache 接收时，才向 LSQ 提供不可失败保证。此时 Store 可以退休，后续 SRAM 写由 Cache 既有流水寄存器持有并完成。缺失、冲突和 MMIO 继续响应后确认。

已接收写跨回滚/LSQ flush 保留；退休后的响应使用在途队列身份排空，不能更新复用槽。退休前沿用 LSQ 逐字节转发，退休后利用 FIFO 顺序及 Cache 行旁路提供最新字节。MMIO 等前序在途 RAM 请求排空，并等待自身响应。断言监测保证命中丢失和退休后写错误。

该实现覆盖已知驻留行，未把一般的推测 Store refill 或独立多项 Store buffer 集成到正式 RTL。

### 结果穿透与并行校验

空写回源槽允许注册执行结果当拍参与树形仲裁，未获完成端口时捕获到原缓冲；反压时锁住输出源。Load 返回经在途/LSQ 标签和错误处理后，可穿透空的 LSQ 完成源。Cache 自身三周期命中延迟保持。

仲裁前按每个实际源的完整 ROB 标签查询活跃、代际、尚未完成状态及物理目的。缓冲源每拍重新查询缓冲标签。合法性与物理目的随结果通过同一个仲裁树，树后排除重复、异常和 x0；ROB 原有完成/分支/异常处理保留，额外断言检查提前广播与 ROB 接收及目的完全一致。

无效写回 payload 保留到下一次填入，使用有效位与选择掩码隔离，降低 reset/pop 清零扇出。

## 2. 同 Cache 配对性能

双方均为 I 1 KiB / D 16 KiB 两路，其他 CPU 参数及外存延迟一致；每项用官方返回值检查。原调查的默认/I 2 KiB 大 Cache 共12项周期也已完全复现。

| --- | ---: | ---: | ---: | ---: | ---: |
| median | 16,642 | 15,530 | 0.418279 | 0.448229 | 7.16% |
| multiply | 23,823 | 22,275 | 0.911808 | 0.975174 | 6.95% |
| qsort | 267,606 | 233,466 | 0.522783 | 0.599231 | 14.62% |

## 3. 依赖链与 Store 微基准

使用同 I1/D16 配对模拟器，独立架构解释器核对返回值，且退休计数与参考一致。均含循环/初始化/退出开销，每项12,800主体操作。

| 微基准 | 原始周期 / IPC | 最终周期 / IPC |
| --- | ---: | ---: |
| ALU 单依赖链 | 25,965 / 0.508723 | 13,237 / 0.997885 |
| ALU 四独立链 | 7,303 / 1.809120 | 7,298 / 1.810359 |
| 地址依赖 Load 链 | 102,507 / 0.128869 | 76,899 / 0.171784 |
| 独立 Load | 14,842 / 0.889974 | 13,247 / 0.997131 |
| 热 Store | 64,375 / 0.205188 | 25,958 / 0.508860 |

热 Store 主体从约5周期/笔降到约2周期/笔；独立 ALU 吞吐基本不变，单链接近翻倍。结果支持优化依赖与确认延迟，不能据此假定所有程序同比加速。

## 4. 拒绝的顺序预取候选

隔离快照新增一项 next-line 外存预取及128位结果缓冲，预取在途时可继续处理 Cache 命中；考虑脏行覆盖与预取错误。它没有集成到正式 RTL。

首版出现“匹配的预取结果被另一在途预取替换”导致等待无对应响应，触发10万周期无退休 watchdog。修正后，六程序结果检查和一个随机 Cache 测试通过，但在当时4项版本上的均值 **0.621299 → 0.606391**（-2.40%）。rsort 周期减少6.37%，vvadd却从8,500增至10,537（+23.96%），D端读行事务300→525。median 的读行事务302→500。

此处读行事务含需求与预取，不能继续把旧计数名 `dcache_refills` 全部解释成需求 refill。额外流量与单行桥接争用抵消了收益。候选因此被拒；未做完整参数/正确性矩阵或 PPA。单项无条件顺序预取不能解决这些多访问流，后续需要需求优先、流识别或跨行事务并行。

## 5. 最终验收与证据边界

- `make unit`、`make lint`：最终版本退出码0，Verilog 2005 RTL 检查及原有完整部件/核心测试通过。
- `make deep-unit`：17组配置通过，包括1/2/4宽度结果反压、恢复/flush、完整 payload、ROB重复/异常/代际复用、LSQ错误/取消、1/2路 Cache 与1/4/8/16项提示、随机替换/部分写，以及已退休写跨回滚/flush。
- 3个故障注入均以非零退出码1被对应断言拒绝：退休后写错误、保证命中丢失、广播授权与 ROB 接收不一致。
- 最终默认16项的完整参数矩阵：81配置、324静态检查；9代表配置各27程序（25官方+2 smoke），共243运行；27条退休差分，共24,849条退休记录。`completed/passed/sources_unchanged` 均为true。
- 另用可确认写接收后无错误的有序测试内存启用核心 Store 提前退休，3代表配置×3种子共9条退休差分、8,283条退休记录全部通过。原矩阵的差分内存模型关闭提前退休；真实 Cache 的延迟写、替换与错误边界由集成/随机测试及官方程序覆盖。
- 最终大 Cache 的官方无观测模拟器：25/25通过，输入/源码/二进制运行前后哈希不变，六项周期与观测模拟器一致。
- 五项微基准与配对基线通过；原调查12项基线周期复现。
- 同配置新 PPA 已完成。IPC/频率联合目标的机器字段明确为 `joint_target_passed=false`。

结果穿透改变了随机轨迹中“同时满宽写回、同时分支完成、错误路径对齐异常”是否恰好重叠。旧断言在关闭穿透时保留；开启穿透后由独立并发、精确异常、重复与代际测试承担，退休差分仍逐条核对架构行为。相关早期覆盖失败原始日志保留，不能算成行为测试通过。

带逐周期 profile 的 `correctness_pi` 初次120秒超时，放宽到600秒后通过（约1,918万周期、退休数与参考一致）。官方无观测模拟器最终约22秒完成该程序。初始位宽 lint、覆盖断言、预取死锁及中止的矩阵均保留；最终验收只引用明确完成的记录。

当前仍需推进一般 Store 提前准备与更充分的缓冲、非阻塞 D-Cache/跨行事务并行，以及端到端恢复/分支供给。Load单依赖链仍约6周期/主体操作，冷缺失数量也未因本次改动减少。最终六程序硬件 MUL/DIV 退休数仍为零。
