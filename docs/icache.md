# 流水线 L1 指令缓存

`rv32_l1_instruction_cache` 是 1 KiB、直接映射、只读的指令缓存，共 64 组，每行 16 字节。取指端以字节地址 PC 请求，返回包含该 PC 的完整 128 位缓存行；最低 8 位对应行首字节。`PC[9:4]` 选组，`PC[31:10]` 为完整标签，`PC[3:2]` 供后续取指级选字。缓存不组装跨行指令包，前端按需要连续请求下一行。

## 内部结构与时序

数据、标签和有效位按组存储。复位只清除有效位。请求和响应之间有三个寄存边界，S0、S1、S2 及响应寄存器各自携带 valid 和原 PC：

| 上升沿 | 工作 |
| --- | --- |
| N | 接收请求，S0 保存 PC。 |
| N+1 | 用 S0 组号同步读取数据、标签和有效位，保存到 S1。 |
| N+2 | 比较 S1 标签，保存命中状态和数据到 S2。 |
| N+3 | 命中数据进入响应寄存器，响应 valid 变高。 |

没有停顿时，四个阶段每拍同时处理不同请求，因此从 N+3 开始每拍可返回一行。响应寄存器被回压时保持内容不变，并通过各级 ready 反向停止前级；这时三周期仅表示无停顿基础延迟。`hit_event_o` 和 `miss_event_o` 是请求在 S2 首次判定时产生的单周期脉冲，内部重读不会重复计数。

## 未命中与局部重读

S2 未命中时冻结 S0、S1 中已接收的后续请求，不再接收新的取指请求。缓存将原 PC 对齐到 16 字节后，通过主存 I 侧 ready/valid 端口发起单笔行读取。主存响应可以在输出端回压期间接收：成功时写入数据、标签和有效位，并将行保存为当前未命中请求的旁路响应；错误时不改写缓存，并返回原 PC、零数据和错误位。

回填可能淘汰 S1 先前读取的同组行。因此原未命中请求进入响应寄存器后，缓存先用保留的 S1 PC **重新读取阵列**，随后才恢复正常流水；S0 仍按原顺序向前推进。这避免后续请求使用过期的命中结果，也不要求取指端重发已经握手的请求。回填写入占用阵列端口，与同步读取不在同一上升沿发生。当前只允许一笔主存请求，活动未命中期间阻塞其他请求。

## Flush 与接线

`flush_i` 在组合接口上立即屏蔽取指响应和新请求，在上升沿清除所有流水 valid。未被主存接受的请求直接取消；已经接受的请求标为废弃，待响应到达后接收并丢弃，绝不将其回填到阵列。重定向后的命中请求可在下一拍开始查找；如果再次未命中，需要等待废弃的旧主存事务排空。复位需与主存同时施加，以共同取消正在进行的事务。

`memory_request_*` 接主存 `i_request_*`，`memory_response_*` 接 `i_response_*`。返回的 PC 和行数据接后续 fetch pipeline，由其取出 `PC[3:2]` 指定的指令并处理跨行 bundle。I 侧没有 D 侧写入侦听；当前 ISA 不支持 `FENCE.I`，不提供自修改代码的一致性保证。

`make icache-lint` 用 Icarus、Verilator 和 Yosys 检查 Verilog 2005 RTL；`make icache-unit` 连接 50 周期主存模型，逐拍验证吞吐、回填、局部重读、回压、flush、错误及随机访问顺序。两个目标分别接入 `make lint`、`make unit`，并有墙钟 timeout。
