# 流水线 L1 指令缓存

`rv32_l1_instruction_cache` 是只读、可参数化的 L1 指令缓存。默认容量为 1 KiB，64 组、1 路、每行 16 字节。`CACHE_SIZE_BYTES`、`NUM_SETS` 与 `NUM_WAYS` 分别配置容量、组数和相联度，并须满足 `CACHE_SIZE_BYTES = NUM_SETS × NUM_WAYS × 16`；组数须为不小于 2 的 2 的幂。默认参数保持原有缓存容量和组数。

每一路的数据阵列和标签阵列均使用官方 `sram_fakeram` 同步 SRAM，valid 位与每组 round-robin 替换指针由寄存器保存。复位只清除 valid 位和替换指针，不初始化 SRAM 内容。索引取 PC 的行偏移之后的 `log2(NUM_SETS)` 位，剩余高位构成完整标签；PC 的低两位供取指级选字。

## 内部结构与时序

请求和响应之间有三个寄存边界，S0、S1、S2 及响应寄存器各自携带 valid 和原 PC：

| 上升沿 | 工作 |
| --- | --- |
| N | 接收请求，S0 保存 PC。 |
| N+1 | S0 组号驱动每一路同步 SRAM 读口，S1 保存 PC 和 valid 快照；SRAM 输出在沿后成为本请求的行和标签。 |
| N+2 | 比较 S1 的各路标签，保存命中路或待替换路及行数据到 S2。 |
| N+3 | 命中数据进入响应寄存器，响应 valid 变高。 |

SRAM 单周期同步读延迟包含在原三周期命中延迟中。无停顿时，四级流水每拍处理不同请求，从 N+3 起每拍可返回一行。SRAM 禁用或写入时读数据未定义，因此运行态持续读当前 S1 组；S1/S2 背压期间也保持正确的数据快照。响应寄存器被回压时保持内容不变，并通过 ready 反向停止前级。

命中时选中匹配路。未命中时优先选择首个 invalid 路；所有路均有效时，按每组 round-robin 指针替换。成功回填后指针移至下一路。`hit_event_o` 和 `miss_event_o` 在 S2 首次判定时产生单周期脉冲，重读不会重复计数。

## 未命中与局部重读

S2 未命中时冻结 S0、S1 中已接收的后续请求，不再接收新请求。缓存将原 PC 对齐到 16 字节后，通过主存 I 侧 ready/valid 端口发起单笔行读取。主存响应可以在输出端回压期间接收：成功时写入选定路的数据、标签和 valid，并将行保存为当前未命中请求的旁路响应；错误时不改写缓存，并返回原 PC、零数据和错误位。

回填可能淘汰 S1 先前读取的同组行。因此原未命中请求进入响应寄存器后，缓存用保留的 S1 PC 重新读取阵列，再恢复正常流水；S0 仍按原顺序向前推进。这避免后续请求使用过期的命中结果，也不要求取指端重发已握手请求。当前只允许一笔主存请求，活动未命中期间阻塞其他请求。

## Flush 与接线

`flush_i` 在组合接口上立即屏蔽取指响应和新请求，在上升沿清除流水 valid。未被主存接受的请求直接取消；已经接受的请求标为废弃，待响应到达后接收并丢弃，绝不回填缓存。重定向后的命中请求可在下一拍开始查找；如果再次未命中，需要等待废弃的旧主存事务排空。复位需与主存同时施加，以共同取消正在进行的事务。

`memory_request_*` 保持 128 位 cache-line 请求接口，`memory_response_*` 保持 128 位回填接口。接入系统时连接 `rv32_l1_cache_axi_bridge` 的 I 侧端口，每行由该桥接层拆成四次 32 位 AXI4-Lite 事务；本地单测仍可直接接仿真主存。返回的 PC 和行数据接后续 fetch pipeline，由其取出 `PC[3:2]` 指定的指令并处理跨行 bundle。I 侧没有 D 侧写入侦听；当前 ISA 不支持 `FENCE.I`，不提供自修改代码的一致性保证。桥接层的仲裁、AXI 握手和错误处理见 [cache_axi_bridge.md](cache_axi_bridge.md)。

`make icache-lint` 检查 RTL 的 Verilog 2005 语法，并用官方 FakeRAM 做层次、可综合性检查；`make icache-unit` 连接固定延迟主存，逐拍验证命中延迟、吞吐、回填、局部重读、回压、flush、错误及参数化 2 路替换。
